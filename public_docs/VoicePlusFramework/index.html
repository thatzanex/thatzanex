Voice Communication Framework

VOICEPLUS

Enterprise-grade, strictly-typed voice communication framework for Roblox, built on the new Audio API (AudioDeviceInput, Wire, AudioEmitter, …). Designed for deep roleplay mechanics: proximity voice with real-time effects, push-to-talk radio frequencies, and always-on full-mesh group calls.

Location (Studio)

ServerScriptService.VoicePlus (ModuleScript + 6 children)

Location (local)

playground/VoicePlus/ (init.luau layout, Rojo-compatible)

Language

Luau, --!strict in every module

Runs on

Server only (clients interact through two RemoteEvents)

Requirements #

RequirementWhy
VoiceChatService.UseAudioApi = Enabled The entire framework is built on the new Audio API instance graph. Start() warns if this is off.
VoiceChatService.EnableDefaultVoice = false VoicePlus creates its own emitters/listeners. Leaving default voice on doubles every voice. Start() warns if this is on.
Voice chat enabled for the experience Set in Creator Hub → Experience → Communication settings.
Voice-eligible, published testing Microphone audio does not flow in solo Studio playtests. Publish and test with voice-eligible accounts (or a voice-enabled Team Test).

Both VoiceChatService properties are already configured correctly in the current place.

Quick Start #

Server script (see ServerScriptService.VoicePlusTest for the full working sample):

server · luau 
local ServerScriptService = game:GetService("ServerScriptService")
local VoicePlus = require(ServerScriptService.VoicePlus)

-- Boot the framework: builds folders + remotes, hooks player lifecycle.
VoicePlus.Start()

-- Push-to-talk radio frequency.
VoicePlus.CreateRadioChannel("Dispatch")

game:GetService("Players").PlayerAdded:Connect(function(player)
    VoicePlus.JoinRadioChannel(player, "Dispatch")
    VoicePlus.ApplyPreset(player, "RadioStatic")
end)

Client push-to-talk (e.g. bound to a key):

client · luau 
local remotes = game:GetService("ReplicatedStorage"):WaitForChild("VoicePlusRemotes")
local transmitToggle = remotes:WaitForChild("VP_TransmitToggle")

transmitToggle:FireServer("Dispatch", true)   -- key down: start transmitting
transmitToggle:FireServer("Dispatch", false)  -- key up: stop

Architecture #

Seven modules, one directional dependency flow. Nothing depends “upward”, so there are no require cycles:

init (VoicePlus) ────────────── entry point, remotes, lifecycle, unified API ├── RadioManager ─┐ ├── GroupManager ─┼──► NodeManager ──► ErrorHandler ├── EffectManager ┘ │ ▲ └── Types ◄────────────────┴────────────────┘ (all modules use Types + ErrorHandler)
ModuleResponsibility
initBoots everything, owns folders/remotes/player lifecycle, exposes the flat public API.
TypesAll exported strict Luau types. No runtime logic.
ErrorHandlerTagged assertions, errors, warnings, and protected calls. The “zero silent failures” layer.
NodeManagerPer-player audio profile (VoiceNode) and the rebuildable signal pipeline.
EffectManagerReal-time voice effects (EQ, distortion, pitch, …) + roleplay presets.
RadioManagerPush-to-talk channels: 1-to-many broadcasting with client sound cues.
GroupManagerAlways-on group calls: many-to-many full-mesh wiring.

Key design decision — the two taps

Every player node exposes exactly two connection points for other systems:

Outbound tap

ProcessedMic

The player’s voice after the effects chain. Radio and group calls source from here, so effects like RadioStatic are heard identically in proximity and over the air.

Inbound tap

InboundFader

The single mixing point for all direct (non-spatial) audio arriving at a player. Any number of wires can target it; the Audio API mixes them. Deafening is a single Volume = 0 on this fader.

04

The Audio Signal Chain #

Per player, built and owned by NodeManager:

OUTBOUND (speaking) Mic (AudioDeviceInput) │ Wire "Chain_<effectId>" (one per effect, in EffectOrder) ▼ [ FX_1 → FX_2 → … → FX_n ] ← effect instances, e.g. AudioEqualizer │ Wire "ChainToProcessed" ▼ ProcessedMic (AudioFader) ← THE outbound tap │ Wire "ProcessedToEmitter" ▼ VP_Emitter (AudioEmitter, on character Head) → heard spatially by nearby players INBOUND — direct audio (radio / group calls) <other player's ProcessedMic> │ Wire "Radio_…" or "Call_…" ▼ InboundFader (AudioFader) ← THE inbound tap (mixes all direct sources) │ Wire "InboundToOutput" (static) ▼ DirectOutput (AudioDeviceOutput) → plays flat on this player's device INBOUND — spatial audio (proximity hearing) VP_Listener (AudioListener, on character Head) │ Wire "ListenerToFader" ▼ ListenerFader (AudioFader) │ Wire "ListenerToOutput" (static) ▼ ListenerOutput (AudioDeviceOutput) → plays world audio on this player's device

Static vs. rebuildable wires. InboundToOutput and ListenerToOutput are created once and never touched. Everything else lives in node.PipelineWires and is destroyed + rerouted by NodeManager._rebuildPipeline() whenever the effect chain changes or the character respawns. Character-dependent segments (emitter/listener) are skipped with a warning when parts are missing — never a crash, never silence about it.

Instance Layout at Runtime #

Created by Start() and CreateNode():

ReplicatedStorage ├── VoicePlusRuntime (Folder) │ └── VP_<UserId> (Folder, one per registered player) │ ├── Mic AudioDeviceInput (.Player = player) │ ├── ProcessedMic AudioFader │ ├── InboundFader AudioFader │ ├── DirectOutput AudioDeviceOutput (.Player = player) │ ├── ListenerFader AudioFader │ ├── ListenerOutput AudioDeviceOutput (.Player = player) │ ├── FX_<effectId> (any active effect instances) │ └── (all Wires owned by this player, incl. radio/group wires they source) └── VoicePlusRemotes (Folder) ├── VP_TransmitToggle RemoteEvent (client → server) └── VP_NotifyClient RemoteEvent (server → client) <player character>.Head (or HumanoidRootPart / PrimaryPart fallback) ├── VP_Emitter AudioEmitter └── VP_Listener AudioListener

Because every instance a player owns lives inside their VP_<UserId> container, teardown is one Container:Destroy() plus table cleanup — nothing can be orphaned.

API Reference #

All functions throw a tagged [VoicePlus ERROR] on invalid input (wrong types, unknown players/channels/calls, duplicates). Anything listed as returning a value returns it on success.

6.3 · EffectManager #

Real-time voice modulation. All changes trigger an automatic pipeline rebuild.

6.4 · RadioManager #

Push-to-talk frequencies: 1-to-many broadcasting, sourced from the transmitter’s ProcessedMic (effects carry over the air).

FunctionReturnsDescription
Init(notifyRemote: RemoteEvent)—Called by Start() with VP_NotifyClient.
CreateChannel(name)RadioChannelCreates a frequency. Throws on duplicates.
DeleteChannel(name)—Stops all live transmissions, detaches all listeners, removes the channel.
GetChannel(name)RadioChannelThrowing lookup.
ChannelExists(name)booleanNon-throwing check.
JoinChannel(player, name)—Tunes the player in. If someone is mid-transmission, the new listener is patched in immediately. Requires a registered node.
LeaveChannel(player, name)—Stops the player’s own transmission, removes them as a listener, and severs every live wire pointed at them — without disturbing other listeners.
SetTransmitting(player, name, enabled: boolean)—Key up / key down. Starting is idempotent, requires channel membership, and is refused (throws) for admin-muted players. Creates one wire per other listener; fires client cues (see §7).
IsTransmitting(player, name)booleanNon-throwing check.
CleanupPlayer(player)—Drops the player from every channel (protected — one bad channel can’t block the rest). Called automatically on leave.

Wiring model: while P transmits on a channel with listeners A, B, C, three wires exist — P.ProcessedMic → A.InboundFader, → B.InboundFader, → C.InboundFader — parented under P’s container and destroyed on key-up.

6.5 · GroupManager #

Always-on, full-mesh group calls (cell phones, dispatch lines). No push-to-talk — everyone hears everyone, always.

FunctionReturnsDescription
CreateCall(callId)GroupCallCreates an empty call. Throws on duplicates.
EndCall(callId)—Destroys every mesh wire and removes the call.
GetCall(callId)GroupCallThrowing lookup.
CallExists(callId)booleanNon-throwing check.
GetParticipants(callId){ Player }Snapshot array of current participants.
AddParticipant(callId, player)—Wires the joiner bi-directionally to every existing participant. Requires a registered node.
RemoveParticipant(callId, player)—Destroys only the wires involving this player; the rest of the mesh is untouched.
CleanupPlayer(player)—Removes the player from every call they’re in (protected). Called automatically on leave.

Wiring model: a call with participants {A, B, C} holds 6 wires (each ordered pair). A 4th joiner adds exactly 6 more (3 out + 3 in); a leaver removes exactly their 2·(n−1).

6.6 · ErrorHandler #

The “zero silent failures” utility used by every module. Also available to your own code via VoicePlus.ErrorHandler.

FunctionDescription
throw(message: string, level: number?)Raises [VoicePlus ERROR] <message>. level works like error()’s relative to your code — the default (1) blames the caller of throw, so the wrapper never appears as the error source.
assert(condition: any, message: string, level: number?): anyTagged assert; returns the condition for inline use: local node = ErrorHandler.assert(find(x), "missing").
warn(message: string, includeTrace: boolean?)Emits [VoicePlus WARNING] <message>, with a stack trace by default (includeTrace = false to suppress).
protect(context: string, fn, ...): booleanRuns fn under pcall. On failure, emits a tagged warning carrying the context string, the inner error, and a stack trace, then returns false. Used for best-effort work (cleanup, character attachment) that must not take the framework down but must never vanish quietly.

Client Integration (Remotes) #

Both remotes live in ReplicatedStorage.VoicePlusRemotes after Start().

VP_TransmitToggle — client → server

signature 
transmitToggle:FireServer(channelName: string, enabled: boolean)

Server-side handling is fully validated: malformed argument types are rejected with a tagged warning, and rule violations (not in the channel, admin-muted) surface as protected warnings — a client can never crash the framework.

VP_NotifyClient — server → client

signature 
notifyClient.OnClientEvent:Connect(function(event: string, channelName: string, transmitter: Player?)
eventFired toMeaning / typical UI reaction
"RadioMicClick"The transmitterTheir own key-up confirmed — play a mic click.
"RadioTransmissionStarted"Every other listenerSomeone keyed up — play the radio beep, show the speaker’s name.
"RadioTransmissionEnded"Every other listenerTransmission over — play squelch tail.

Example client cue handler:

client · luau 
local remotes = game:GetService("ReplicatedStorage"):WaitForChild("VoicePlusRemotes")
remotes.VP_NotifyClient.OnClientEvent:Connect(function(event, channel, transmitter)
    if event == "RadioTransmissionStarted" then
        beepSound:Play()
    elseif event == "RadioTransmissionEnded" then
        squelchSound:Play()
    elseif event == "RadioMicClick" then
        clickSound:Play()
    end
end)

Effect Presets #

Applied with VoicePlus.ApplyPreset(player, name), removed with RemovePreset. Each preset’s effect ids are namespaced (<Preset>_<Role>), so RemovePreset surgically removes its own effects and never touches manually added ones. ApplyPreset skips ids that already exist, making it idempotent.

MuffledHelmet

MuffledHelmet_EQ — AudioEqualizer (Low +2, Mid −12, High −60)

Voice through a sealed helmet: highs killed, mids damped.

RadioStatic

RadioStatic_EQ — AudioEqualizer (Low −30, Mid +6, High −20) → RadioStatic_Distortion — AudioDistortion (0.35)

Crackly two-way radio: band-passed and gritted.

Megaphone

Megaphone_EQ — AudioEqualizer (Low −24, Mid +10, High −6) → Megaphone_Distortion — AudioDistortion (0.15)

Honky, mid-forward PA blare with light clip.

To add a preset, extend the PRESETS table in EffectManager.luau — follow the id-namespacing convention so removal stays surgical.

Because presets sit before ProcessedMic, they color the voice everywhere: proximity, radio, and group calls alike.

09

Error Handling Philosophy #

Zero silent failures. Every failure path is either a thrown, tagged error or a tagged warning with a stack trace:

Throw ([VoicePlus ERROR]) when the caller did something wrong: invalid types, unregistered players, unknown channels/calls/presets, duplicate creation, invalid effect properties, transmitting while admin-muted. These are programming/logic errors and should fail loudly during development.

Warn + continue ([VoicePlus WARNING]) when the world is imperfect but the framework can proceed: a character missing its Head, a partial pipeline rebuild, a malformed client remote, VoiceChatService misconfiguration, one channel failing during multi-channel cleanup.

ErrorHandler.protect wraps every best-effort region (player join/leave, character attach, per-channel cleanup) so one failure is reported with full context but never cascades — a broken channel can’t block a player’s other cleanups.

Blame levels are propagated (level parameters) so errors point at your call site, not at the framework’s internals.

Memory & Lifecycle Guarantees #

When PlayerRemoving fires (or you call UnregisterPlayer), the cleanup chain runs in order:

  1. 01

    RadioManager.CleanupPlayer — leaves every channel: destroys the player’s transmission wires and every wire targeting them; other listeners keep receiving uninterrupted.

  2. 02

    GroupManager.CleanupPlayer — unlinks them from every call’s mesh; wires between remaining participants are untouched.

  3. 03

    NodeManager.CleanupPlayer — disconnects CharacterAdded/CharacterRemoving connections, destroys VP_Emitter/VP_Listener, destroys the whole VP_<UserId> container (all faders, outputs, effects, and wires), and table.clears every nested table before dropping the node reference.

Structural guarantees that make leaks impossible by construction

  • Every instance a player owns lives in their container → one Destroy() collects everything, including wires created by radio/group systems (they’re parented to the source player’s container).
  • Player-keyed dictionaries (_nodes, Listeners, Participants, MeshWires, …) are explicitly nil’d, so Player objects are never retained after leave.
  • Each cleanup step is protect-wrapped: a failure in one manager is reported but never prevents the others from running.

Extending the Framework #

Custom direct-audio systems (intercoms, phone-to-phone, spectator feeds): source from NodeManager.GetProcessedMic(speaker) and target NodeManager.GetInboundFader(listener) — you inherit effects, admin-mute, and deafen behavior for free:

custom wiring · luau 
local wire = Instance.new("Wire")
wire.SourceInstance = VoicePlus.NodeManager.GetProcessedMic(speaker)
wire.TargetInstance = VoicePlus.NodeManager.GetInboundFader(listener)
wire.Parent = VoicePlus.GetVoiceNode(speaker).Container  -- auto-cleaned on leave

World speakers (PA systems, radios on tables): wire a ProcessedMic into an AudioEmitter you place on a world part — everyone nearby hears the broadcast spatially.

New effect classes: add the class name to VALID_EFFECT_CLASSES in EffectManager.luau (keep the whitelist — it’s what turns typos into loud errors instead of mystery silence).

Wire compatibility rules (enforced by construction in createWire call sites): sources are audio producers (AudioDeviceInput, effects, AudioFader, AudioListener); targets are audio consumers (effects, AudioFader, AudioEmitter, AudioDeviceOutput). Every wire in the framework sets SourceInstance and TargetInstance as a matched pair before parenting.

Troubleshooting #

SymptomLikely cause / fix
Total silence in Studio playtestExpected — mic audio doesn’t flow in solo playtests. Publish and test with voice-eligible accounts.
[VoicePlus WARNING] VoiceChatService.UseAudioApi is not EnabledSet VoiceChatService.UseAudioApi = Enabled in Studio and republish.
Everyone’s voice is doubledVoiceChatService.EnableDefaultVoice is on — turn it off; VoicePlus owns the voice graph.
[VoicePlus ERROR] No VoiceNode registered for XYou called an API before the player was registered. Either keep AutoRegisterPlayers on, or call RegisterPlayer first (mind the race on PlayerAdded — Start() must be called before your own PlayerAdded handlers connect).
Player heard in proximity but not over radioThey aren’t transmitting (SetTransmitting true requires prior JoinChannel), or they’re admin-muted. Check IsTransmitting.
No spatial voice for one playerTheir character lacks Head/HumanoidRootPart/PrimaryPart at spawn — look for the spatial voice deferred warning; the emitter attaches on next respawn with valid parts.
Effect add throws Invalid propertyProperty name or value doesn’t exist on that effect class — the message includes the class, effect id, and inner engine error.
Radio cues never play on clientsYou haven’t connected VP_NotifyClient.OnClientEvent (see §7) — the server only fires events; sounds are the client’s job.
